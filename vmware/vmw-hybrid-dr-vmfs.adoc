= 適用於 VMFS 資料儲存的 NetApp Disaster Recovery
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
使用從生產站點到災難復原站點的區塊級複製進行災難復原是一種有彈性且經濟高效的方法，可保護工作負載免受網站中斷和資料損壞事件（如勒索軟體攻擊）的影響。透過NetApp SnapMirror複製，使用 VMFS 資料儲存區運行本地ONTAP系統的 VMware 工作負載可以複製到 VMware 所在的指定復原資料中心的另一個ONTAP儲存系統

本文件的此節說明 NetApp Disaster Recovery 的組態，以為內部部署 VMware VM 設定災難恢復至另一個指定站台。做為此設定的一部分，包括 Console 代理程式、上線 ONTAP 陣列、定義站台以及關聯 VMware vCenter。此外，本文件詳細說明如何設定站台之間的複寫，以及如何設定與測試恢復計畫。最後一節提供執行完整站台容錯移轉的指示，以及在主站台恢復並上線時如何進行容錯回復。

運用 NetApp Data Services 的災難恢復功能，客戶可以探索其內部部署的 VMware vCenters 以及 ONTAP 儲存設備，建立資源群組，建立災難恢復計畫，將其與資源群組建立關聯，並測試或執行容錯移轉與容錯回復。SnapMirror 提供儲存層級的區塊複寫，透過遞增變更讓兩個站台保持最新狀態，進而達成最短 5 分鐘的 RPO。此外，也可以將 DR 程序模擬為常規演練，而不會影響生產環境與複寫的資料存放區，也不會產生額外儲存容量成本。NetApp Data Services 運用 ONTAP 的 FlexClone 技術，從 DR 站台上最後一次複寫的 Snapshot 快照技術，建立 VMFS 資料存放區極具空間效率的複本。DR 測試完成後，客戶只需刪除測試環境即可，同樣不會對實際複寫的生產資源造成任何影響。當需要（計畫內或計畫外）進行實際容錯移轉時，只需按幾下，災難恢復功能即可協調所有必要步驟，自動在指定的災難恢復站台上啟動受保護的虛擬機器。該服務也會反轉與主要站台的 SnapMirror 關係，並在需要時將任何變更從次要站台複寫到主要站台，以進行容錯回復作業。與其他知名替代方案相比，只需極低的成本即可達成所有這些目標。

image:dr-draas-vmfs-030.png["此圖顯示輸入/輸出對話框或表示書面內容"]


NOTE: 如需用於災難恢復的 vCenter Server、ESXi 和 ONTAP 的最新資訊與支援版本，請參閱 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/get-started/dr-intro.html["災難恢復支援的組態"]。



[[getting-started]]
== 入門

若要開始使用災難恢復，請使用 NetApp Console，然後存取服務。

. 登入控制台。
. 從主控台左側導覽中，選取「保護」>「災難恢復」。
. 災難恢復儀表板隨即顯示。


image:dr-draas-vmfs-001.png["此圖顯示輸入/輸出對話框或表示書面內容"]

在配置災難復原計畫之前，請確保滿足以下先決條件：

* 控制台代理程式已部署在 AWS VPC 中。
* 控制台代理程式執行個體與來源和目的地 vCenter 及儲存系統具有連線能力。
* 為 VMware 託管 VMFS 資料存放區的內部部署 NetApp 儲存系統已新增至 Console。
* 使用 DNS 名稱時應該進行 DNS 解析。否則，請使用 vCenter 的 IP 位址。
* SnapMirror複製是為指定的基於 VMFS 的資料儲存磁碟區配置的。


一旦來源站點和目標站點之間建立連接，請繼續執行設定步驟，這大約需要 3 到 5 分鐘。


NOTE: NetApp 建議將主控台代理程式部署在災難恢復站台或第三個站台，以便主控台代理程式在實際中斷或自然災害期間，可以透過網路與來源和目的地資源進行通訊。

image:dr-draas-vmfs-002.png["此圖顯示輸入/輸出對話框或表示書面內容"]


NOTE: 在撰寫本文檔時，對本地到本機 VMFS 資料儲存的支援處於技術預覽階段。基於 FC 和 ISCSI 協定的 VMFS 資料儲存均支援此功能。

[[configuring-storage-replication-between-source-and-destination-site]]
== 配置來源站點和目標站點之間的儲存複製

SnapMirror利用ONTAP快照來管理從一個位置到另一個位置的資料傳輸。首先，基於來源磁碟區快照的完整副本被複製到目標位置以執行基線同步。當來源處發生資料變更時，會建立一個新的快照並將其與基準快照進行比較。然後將發現已更改的區塊複製到目標位置，其中較新的快照成為當前基線或最新的公共快照。這使得該過程可以重複，並且可以將增量更新發送到目的地。

建立SnapMirror關係後，目標磁碟區處於線上唯讀狀態，因此仍可存取。 SnapMirror與實體儲存區塊一起工作，而不是在檔案或其他邏輯層級上工作。這意味著目標磁碟區是來源的相同副本，包括快照、磁碟區設定等。如果來源磁碟區正在使用ONTAP空間效率功能（例如資料壓縮和重複資料刪除），則複製的磁碟區將保留這些最佳化。

中斷SnapMirror關係會使目標磁碟區變得可寫，並且通常在使用SnapMirror將資料同步到 DR 環境時用於執行故障轉移。  SnapMirror足夠複雜，可以允許故障轉移網站上更改的資料有效地重新同步回主系統（如果主系統稍後恢復上線），然後允許重新建立原始的SnapMirror關係。



[[how-to-set-it-up-for-vmware-disaster-recovery]]
== 如何設定 VMware 災難復原

建立 SnapMirror 複寫的程序對於任何指定的應用程式皆相同。此程序可以是手冊或自動化。最簡單的方法是運用 Console 來設定 SnapMirror 複寫，只需將環境中的來源 ONTAP 系統拖放至目的地，即可觸發精靈來引導完成其餘程序。

image:dr-draas-vmfs-006.png["此圖顯示輸入/輸出對話框或表示書面內容"]

NetApp Data Services 也可以自動化相同的作業，前提是符合下列兩個條件：

* 源集群和目標集群具有對等關係。
* 源 SVM 和目標 SVM 具有對等關係。


image:dr-draas-vmfs-007.png["此圖顯示輸入/輸出對話框或表示書面內容"]


NOTE: 如果已透過 CLI 為 Volume 設定 SnapMirror 關係，Console 會取得該關係並繼續執行其餘的工作流程操作。


NOTE: 除了上述方法外，也可以透過 ONTAP CLI 或 System Manager 建立 SnapMirror 複寫。無論採用何種方法使用 SnapMirror 同步資料，災難恢復都會協調工作流程，以實現無縫且有效率的災難恢復作業。



[[what-can-disaster-recovery-do-for-you]]
== 災難恢復能為您帶來什麼好處？

新增來源和目的地站台後，災難恢復會自動執行深度探索，並顯示虛擬機器及其關聯的中繼資料。災難恢復也會自動偵測虛擬機器使用的網路和連接埠群組，並將其填入。

image:dr-draas-vmfs-008.png["此圖顯示輸入/輸出對話框或表示書面內容"]

新增站台後，即可將虛擬機器分組到資源群組。災難恢復資源群組可讓您將一組相依的虛擬機器分組到邏輯群組中，這些邏輯群組包含其開機順序和開機延遲，以便在恢復時執行。若要開始建立資源群組，請導覽至 *資源群組* ，然後按一下 *建立新資源群組* 。

image:dr-draas-vmfs-009.png["此圖顯示輸入/輸出對話框或表示書面內容"]


NOTE: 在建立複製計劃時也可以建立資源組。

可以透過簡單的拖放機制在建立資源群組期間定義或修改虛擬機器的啟動順序。

image:dr-draas-vmfs-010.png["此圖顯示輸入/輸出對話框或表示書面內容"]

建立資源群組後，下一步是建立執行藍圖或在災難發生時復原虛擬機器和應用程式的計畫。如先決條件中所述，可以預先配置SnapMirror複製，或者 DRaaS 可以使用在建立複製計劃期間指定的 RPO 和保留計數來配置它。

[[what-happens-during-a-failover-or-test-failover-operation]]
== 故障轉移或測試故障轉移操作期間會發生什麼？

在測試容錯移轉作業期間，災難恢復會使用目的地 Volume 的最新 Snapshot 複本或選定的快照，在目的地 ONTAP 儲存系統上建立 FlexClone Volume。


NOTE: 測試故障轉移操作會在目標ONTAP儲存系統上建立複製磁碟區。


NOTE: 執行測試恢復操作不會影響SnapMirror複製。

image:dr-draas-vmfs-024.png["此圖顯示輸入/輸出對話框或表示書面內容"]

在此過程中，災難恢復不會對應原始目標 Volume。相反地，它會從選定的 Snapshot 快照技術建立一個新的 FlexClone Volume，並將支援該 FlexClone Volume 的暫存資料存放區對應至 ESXi 主機。

image:dr-draas-vmfs-025.png["此圖顯示輸入/輸出對話框或表示書面內容"]

image:dr-draas-vmfs-026.png["此圖顯示輸入/輸出對話框或表示書面內容"]

當測試容錯移轉作業完成時，可以使用 *"Clean Up failover test"* 觸發清理作業。在此作業期間，災難恢復會銷毀在作業中使用的 FlexClone Volume。

若發生真實的災難事件，災難恢復會執行下列步驟：

. 中斷站點之間的SnapMirror關係。
. 重新簽署後掛載 VMFS 資料儲存磁碟區以供立即使用。
. 註冊虛擬機
. 啟動虛擬機


image:dr-draas-vmfs-027.png["此圖顯示輸入/輸出對話框或表示書面內容"]

主站台啟動並運作後，災難恢復可為 SnapMirror 啟用反向重新同步並啟用容錯回復，同樣只需按一下按鈕即可執行。

image:dr-draas-vmfs-028.png["此圖顯示輸入/輸出對話框或表示書面內容"]

如果選擇遷移選項，則它將被視為計劃內的故障轉移事件。在這種情況下，將觸發額外的步驟，即關閉來源站點的虛擬機器。其餘步驟與故障轉移事件相同。

從 Console 或 ONTAP CLI，您可以監控適當資料存放區 Volume 的複寫健全狀況，並可透過作業監控來追蹤容錯移轉或測試容錯移轉的狀態。

image:dr-draas-vmfs-029.png["此圖顯示輸入/輸出對話框或表示書面內容"]

這為處理量身定制的災難復原計劃提供了強大的解決方案。當發生災難並決定啟動 DR 站點時，可以按計劃進行故障轉移或單擊按鈕進行故障轉移。

要了解有關此過程的更多信息，請隨意觀看詳細的演示視頻或使用link:https://netapp.github.io/bluexp-draas-vmfs-simulator/?frame-0.1["解決方案模擬器"]。
