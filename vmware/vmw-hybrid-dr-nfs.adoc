[[netapp-disaster-recovery-for-nfs-datastores]]
== 適用於 NFS 資料存放區的 NetApp Disaster Recovery

[role="lead"]
透過從生產站點到災難復原站點的區塊級複製來實現災難復原是一種具有彈性且經濟高效的方法，可保護工作負載免受網站中斷和資料損壞事件（例如勒索軟體攻擊）的影響。使用NetApp SnapMirror複製，在具有 NFS 資料儲存的本機ONTAP系統上執行的 VMware 工作負載可以複製到位於指定復原資料中心的另一個ONTAP儲存系統，該資料中心也部署了 VMware。

本文件的這一節說明 NetApp Disaster Recovery 的組態，以便為內部部署 VMware VM 設定至另一個指定站台的災難恢復。作為此設定的一部分，包括 Console 代理程式、將 ONTAP 陣列上線、定義站台以及關聯 VMware vCenter。此外，本文件詳細說明如何設定站台之間的複寫，以及如何設定與測試恢復計畫。最後一節提供執行完整站台容錯移轉的指示，以及在主要站台恢復並處於線上狀態時如何進行容錯回復。

利用 NetApp Data Services 中的災難恢復功能，企業可以輕鬆探索其內部部署的 VMware vCenters 和 ONTAP 儲存設備。然後，組織可以建立資源群組、建立災難恢復計畫、將其與資源群組建立關聯，並測試或執行容錯移轉與容錯回復。SnapMirror 提供儲存層級的區塊複寫，透過遞增變更讓兩個站台保持最新狀態，進而達成最多 5 分鐘的復原點目標（RPO）。此外，還可以模擬災難恢復程序，而不會影響正式作業或產生額外儲存容量成本。

災難恢復利用 ONTAP 的 FlexClone 技術，從災難恢復站台上最後一次複寫的 Snapshot 快照技術建立 NFS 資料儲存的極具空間效率複本。完成災難恢復測試後，客戶可以輕鬆刪除測試環境，而不會影響實際複寫的生產資源。如果發生實際容錯移轉，災難恢復會協調所有必要步驟，只需按幾下即可在指定的災難恢復站台上自動啟動受保護的虛擬機器。該服務也會在需要時反轉與主站台的 SnapMirror 關係，並將次要站台的任何變更複寫到主站台，以執行回復作業。與其他知名替代方案相比，所有這些功能的成本都低得多。

image:dr-draas-nfs-001.png["此圖顯示輸入/輸出對話框或表示書面內容"]


NOTE: 如需用於災難恢復的 vCenter Server、ESXi 和 ONTAP 的最新資訊與支援版本，請參閱 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/get-started/dr-intro.html["災難恢復支援的組態"]。



[[getting-started]]
=== 入門

若要開始使用 NetApp 災難恢復，請使用 NetApp 控制台，然後存取服務。

. 登入控制台。
. 從主控台左側導覽中，選擇 保護 > 災難恢復。
. 災難恢復儀表板隨即顯示。
+
image:dr-draas-nfs-002.png["此圖顯示輸入/輸出對話框或表示書面內容"]



在設定災難恢復計畫之前，請確保滿足以下先決條件：

* 主控台代理程式已部署。
* 代理程式可連線至來源和目的地 vCenter 與儲存系統。
* 已啟用 NFS 服務的 ONTAP 叢集 SVM 可用。
* 託管 VMware NFS 資料存放區的內部部署 NetApp 儲存系統已在 Console 中新增。
* 使用 DNS 名稱時應該進行 DNS 解析。否則，請使用 vCenter 的 IP 位址。
* SnapMirror複製是為指定的基於 NFS 的資料儲存庫磁碟區配置的。
* 確保環境具有支援的 vCenter Server 和 ESXi 伺服器版本。


一旦來源站點和目標站點之間建立了連接，請繼續執行設定步驟，這需要幾次點擊和大約 3 到 5 分鐘的時間。


NOTE: NetApp 建議將 Console 代理程式部署在目的地站台或第三個站台，以便 Console 代理程式可以透過網路與來源和目的地資源進行通訊。

[[configuring-storage-replication-between-source-site-array-and-destination-site-array]]
=== 配置來源站點陣列和目標站點陣列之間的儲存複製

SnapMirror 在 NetApp 環境中提供資料複寫功能。SnapMirror 複寫以 NetApp Snapshot 快照技術為基礎，效率極高，因為它只複寫自上次更新以來已變更或新增的區塊。SnapMirror 可透過 NetApp OnCommand System Manager 或 ONTAP CLI 輕鬆設定。NetApp Data Services 也可建立 SnapMirror 關係，前提是事先設定叢集與 SVM 對等關係。

對於主儲存設備未完全遺失的情況，SnapMirror 提供了一種重新同步主站台和災難恢復站台的高效方法。SnapMirror 可以重新同步這兩個站台，只需反轉 SnapMirror 關係，即可僅將變更或新增的資料從災難恢復站台傳回主站台。這意味著在災難恢復中，容錯移轉後可以雙向重新同步複寫計畫，而無需重新複製整個 Volume。如果以相反方向重新同步關係，則只會將自上次成功同步 Snapshot 複本以來寫入的新資料傳回目的地。


NOTE: 如果已透過 CLI 或 System Manager 為 Volume 設定 SnapMirror 關係，NetApp Data Services 會取得該關係，並繼續執行其餘的工作流程作業。

[[test-failover]]
=== 測試故障轉移

災難恢復中的測試容錯移轉是一項操作程序，可讓 VMware 系統管理員在不中斷生產環境的情況下，全面驗證其恢復計畫。在測試容錯移轉期間，災難恢復會在災難恢復儲存系統上，建立複寫的 NFS 資料存放區 Volume 的極具空間效率 NetApp FlexClone 複本。然後，這些 FlexClone Volume 會掛載到災難恢復站台的 ESXi 主機，並在隔離的測試網路中將虛擬機器開機。此程序可讓系統管理員驗證其災難恢復計畫在發生實際災難時，是否能如預期運作。

image:dr-draas-nfs-024.png["此圖顯示輸入/輸出對話框或表示書面內容"]

災難恢復包含在測試容錯移轉作業中選擇 Snapshot 複本做為選用功能的能力。此功能可讓 VMware 系統管理員驗證環境中最近所做的任何變更是否已複寫到目的地站台，從而在測試期間呈現。此類變更包括虛擬機器客體作業系統的修補程式

image:dr-draas-nfs-025.png["此圖顯示輸入/輸出對話框或表示書面內容"]

當 VMware 系統管理員執行測試容錯移轉作業時，災難恢復會自動化下列工作：

* 觸發SnapMirror關係，使用生產網站上所做的任何最新變更來更新目標網站上的儲存空間。
* 在 DR 儲存陣列上建立FlexVol磁碟區的NetApp FlexClone磁碟區。
* 將FlexClone磁碟區中的 NFS 資料儲存庫連接到 DR 站點的 ESXi 主機。
* 將虛擬機器網路介面卡連接到映射期間指定的測試網路。
* 依照 DR 站點的網路定義重新配置 VM 客戶作業系統網路設定。
* 執行複製計劃中儲存的任何自訂命令。
* 依照複製計畫中定義的順序啟動虛擬機器。
+

清理故障轉移測試操作在複製計劃測試完成並且 VMware 管理員回應清理提示後發生。

image:dr-draas-nfs-027.png["此圖顯示輸入/輸出對話框或表示書面內容"]

. 它關閉用於測試的FlexClone副本中的每個恢復的虛擬機器。
. 它會刪除在測試期間用於呈現復原的虛擬機器的 FlexClone磁碟區。




[[planned-migration-and-fail-over]]
=== 計劃遷移和故障轉移

災難恢復有兩種執行真正容錯移轉的方法：計畫性移轉和容錯移轉。第一種方法是計畫性移轉，將虛擬機器關機和儲存設備複寫同步整合到流程中，以恢復或有效地將虛擬機器移轉到目的地站台。計畫性移轉需要存取來源站台。第二種方法是容錯移轉，這是一種計畫性/非計畫性的容錯移轉，其中虛擬機器會在目的地站台，從上一次成功完成的儲存設備複寫間隔中恢復。根據解決方案中設計的 RPO，在災難恢復情境中可能會出現一定程度的資料遺失。

image:dr-draas-nfs-028.png["此圖顯示輸入/輸出對話框或表示書面內容"]

當 VMware 系統管理員執行容錯移轉作業時，災難恢復會自動化下列任務：

* 中斷並故障轉移NetApp SnapMirror關係。
* 將複製的 NFS 資料儲存連接到 DR 站點的 ESXi 主機。
* 將 VM 網路介面卡連接到適當的目標站點網路。
* 依照目標站點的網路定義重新配置 VM 客戶作業系統網路設定。
* 執行複製計劃中儲存的任何自訂命令（如果有）。
* 依照複製計畫中定義的順序啟動虛擬機器。


image:dr-draas-nfs-029.png["此圖顯示輸入/輸出對話框或表示書面內容"]



[[failback]]
=== 故障回覆

故障回復是一種選用過程，可在復原後還原來源站台和目標站台的原始設定。

image:dr-draas-nfs-030.png["此圖顯示輸入/輸出對話框或表示書面內容"]

當 VMware 管理員準備將服務還原到原始來源網站時，他們可以設定並執行故障回應程式。

*注意：*災難恢復會在反轉複寫方向之前，將任何變更複寫（重新同步）回原始來源虛擬機器。此程序從已完成容錯移轉至目標的關係開始，並包含下列步驟：

* 關閉並取消註冊虛擬機，並卸載目標網站上的磁碟區。
* 打破原始來源上的SnapMirror關係，使其變成讀/寫。
* 重新同步SnapMirror關係以逆轉複製。
* 在來源上安裝卷，啟動並註冊來源虛擬機器。


如需存取與設定災難恢復的詳細資訊，請參閱link:https://docs.netapp.com/us-en/data-services-disaster-recovery/get-started/dr-intro.html["了解適用於 VMware 的 NetApp Disaster Recovery"]。
